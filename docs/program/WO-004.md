# WO-004 -- Fast unit tests (pytest) beside run_checks.py

Why: run_checks.py is one 424 KB file that takes 15-20 minutes; nobody can run it after each edit, and many
of its assertions read source text. We start a fast suite; run_checks.py stays until its checks are moved.
Branch: `wo-004-pytest`
Files you may change: tests/** (new), requirements-dev.txt (new), pytest.ini (new), run_checks.py (ONLY to
delete a check that you moved, one for one), docs/program/reports/WO-004.md.

## Steps
1. Branch. requirements-dev.txt: `pytest==8.*`. pytest.ini: testpaths = tests/unit.
2. tests/conftest.py: put the repo root on sys.path and install the same stand-ins run_checks.py installs at
   its top for missing desktop packages (copy that block; do not import run_checks).
3. Move, as real behavioural tests (no assertions on source text), the checks for exactly these four pure
   modules, one test file each: command_policy, world_sensor, coder (with the fake process), core/reader.
   Each test file must run alone: `venv\Scripts\python.exe -m pytest tests\unit\test_<name>.py -q`.
4. For each check you moved completely, delete it from run_checks.py and from its final list. If a check
   also covers other modules, leave it and note it in the report.
5. Run `venv\Scripts\python.exe -m pytest -q` (must take < 20 s) and the full run_checks.py.
6. Report, PR.

## Acceptance
- pytest: all pass, < 20 s, output pasted. run_checks.py: `All checks passed.`
- No test reads a .py/.html file to assert on its text. No product code changed.
