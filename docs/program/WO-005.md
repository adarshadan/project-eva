# WO-005 -- CI run on every push to main

Why: three contributors pushed to main directly. Work now goes straight to main, so every push must be checked on a clean
Windows machine and a red run must be fixed (or reverted) before any other work.
Rollback point: tag `pre-wo-005` (create and push it before the first change).
Files you may change: .github/workflows/windows-checks.yml, docs/program/reports/WO-005.md.

## Steps
1. `git pull`, tag `pre-wo-005`, push the tag. In the workflow: trigger on push to main (and workflow_dispatch); add a step before "Run checks":
   `python -m pip install -r requirements-dev.txt` then `python -m pytest -q`; add a step
   `python main.py --selftest`; add `actions/setup-node@v4` (node 20) and a step `node tools/motion_test.js`.
   Keep the existing run_checks and soak steps.
2. Push and wait for the run (GitHub -> Actions). If a step fails on the clean machine but passes on the PC, paste
   the failing output in the report and STOP (do not edit product code or checks to make it green).
3. Add to GEMINI.md rule 2 one sentence: after every push, check the Actions run; if it is red, fix or
   `git revert` that commit before doing anything else. (GEMINI.md is allowed for this one line.)
4. Report.

## Acceptance
- The run for the last commit is green with all five steps; the run URL is in the report.
