# WO-005 -- CI gate on every pull request

Why: three contributors pushed to main directly. From now on main only changes through a pull request that
passed the checks on a clean Windows machine.
Branch: `wo-005-ci`
Files you may change: .github/workflows/windows-checks.yml, docs/program/reports/WO-005.md.

## Steps
1. Branch. In the workflow: trigger on pull_request and on push to main only; add a step before "Run checks":
   `python -m pip install -r requirements-dev.txt` then `python -m pytest -q`; add a step
   `python main.py --selftest`; add `actions/setup-node@v4` (node 20) and a step `node tools/motion_test.js`.
   Keep the existing run_checks and soak steps.
2. Push, open the PR, wait for the run. If a step fails on the clean machine but passes on the PC, paste
   the failing output in the report and STOP (do not edit product code or checks to make it green).
3. Tell the Director the exact GitHub setting to enable (he does it; you do not have that permission):
   Settings -> Branches -> Add rule for `main` -> Require a pull request before merging + Require status
   checks to pass (select `checks`).
4. Report.

## Acceptance
- The PR shows the workflow green with all five steps; the run URL is in the report.
- Branch protection is on (the Director confirms).
